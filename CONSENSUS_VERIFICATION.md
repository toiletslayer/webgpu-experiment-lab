## Header Serialization

CapStash Core builds the mining header as exactly 80 bytes:

| Offset | Size | Field | Encoding |
| --- | ---: | --- | --- |
| 0 | 4 | `nVersion` | little-endian `uint32` |
| 4 | 32 | `hashPrevBlock` | raw internal `uint256` bytes |
| 36 | 32 | `hashMerkleRoot` | raw internal `uint256` bytes |
| 68 | 4 | `nTime` | little-endian `uint32` |
| 72 | 4 | `nBits` | little-endian `uint32` |
| 76 | 4 | `nNonce` | little-endian `uint32` |

`uint256` display hex is reversed compared with internal bytes. The browser implementation accepts display hex for hashes, reverses it into internal bytes for serialization, and reverses internal PoW bytes for Core-style display.

## Whirlpool Implementation

CapStash Core wraps SPHlib plain WHIRLPOOL:

- `CWhirlpool512::Write()` calls `sph_whirlpool`.
- `CWhirlpool512::Finalize()` calls `sph_whirlpool_close`.
- The active variant is plain WHIRLPOOL, not WHIRLPOOL-0 or WHIRLPOOL-1.

The JavaScript reference uses constants generated from Core's `plain_T0` and `plain_RC` tables and matches known WHIRLPOOL vectors for empty string and `abc`.

## XOR Folding

Core folds the 64-byte Whirlpool digest to 32 bytes:

```text
out[i] = whirlpool[i] ^ whirlpool[i + 32], for i = 0..31
```

The folded bytes are copied directly into a `uint256`.

## PoW Validation

`CheckProofOfWork(const CBlockHeader&, params)` computes:

```text
powhash = block.GetPoWHash()
CheckProofOfWork(powhash, block.nBits, params)
```

The browser prototype does not validate chain difficulty or mine against a live target. It only verifies that header hashing is byte-identical to the audited Core path.

## Current Assumptions

- Browser benchmark labels must remain conservative until the WGSL implementation passes the generated Core vectors in a WebGPU-capable browser run.
